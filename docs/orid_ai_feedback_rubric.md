# AI–ORID Feedback Rubric（研究用引導規準）

> 文件角色：**AI feedback 與人評對齊的研究規準**（奇數週 ORID、偶數週整合、SEL、實驗／控制差異）  
> 建立日期：2026-08  
> 研究脈絡見 [`research_design_context.md`](research_design_context.md)。  
> **本 Phase 1 只定文件**；不代表已改 runtime prompt。現行程式行為若不同，文中以「現況／目標」標註。

---

## 一、AI feedback 設計目的

AI 是實驗組研究處理的一部分，需對準：

1. **RQ1**：支持 ORID 架構下的反思寫作表現  
2. **RQ2**：支持反思寫作中的 SEL 表現  
3. **RQ3**：促進修改、補充與再次思考（進而反映在投入／修正歷程指標）

正式 RQ1／RQ2 分析以**人工 rubric**為主；系統自動分數為過程／探索用（見研究脈絡文件）。

---

## 二、AI feedback 共通原則

1. **不可**直接幫學生寫完整答案或代替完成作文。  
2. 回饋須為**引導式**：問題、提示、方向建議。  
3. 語氣適合國小五年級：溫和、鼓勵、清楚。  
4. 建議固定**三段式**（標題用字與現行敘事一致）：  
   - 你已經做到：  
   - 再想一想：  
   - 可以這樣修改：  
5. 「可以這樣修改」只給句型方向或**半句／小範例**，避免可整段複製的完整答案。  
6. 鼓勵學生**回到自己的文字**修改，而非複製 AI 全文。  
7. 每次回饋原則上**只挑一個最重要缺口**（單點引導），以利 RQ3 的修正行為。  
8. 回覆宜為純文字學生可讀格式（現行 playbook 禁止 Markdown 粗體記號等）。

## 三、奇數週 ORID 分段寫作 AI feedback rubric

適用：第 1、3、5 週；`source=feedback_button`；階段 `O`／`R`／`I`／`D`。

系統主向度 ID：`O1`、`R1`、`I1`、`D1`（`fastapi_backend/app/content/rubrics.py`）。  
系統通過規則（實作）：ORID 主向度達標（約層級 ≥ 3）才 `ok=true`；**SEL 不決定** `feedback_ok`。

### 3.1 O — Objective 觀察

| | 內容 |
|--|------|
| **檢查** | 是否寫出故事中的具體事件；是否提到角色、情節、發生的事 |
| **引導** | 不要只寫模糊感受；把「誰、做了什麼、哪一幕」寫清楚 |
| **系統對照** | `O1` 客觀事實；O 段 SEL `by_stage` 為空 |
| **人評重點（RQ1）** | 事實具體度、與文本對得上 |

### 3.2 R — Reflective 感受

| | 內容 |
|--|------|
| **檢查** | 是否寫出自己的感受；是否說明為什麼；是否連回故事事件 |
| **引導** | 把感受扣到「書裡哪一幕」；原因說清楚 |
| **系統對照** | `R1`；輔助 SEL：`SEL_SA`（情緒覺察）、`SEL_SOA`（同理）、必要時 `SEL_SM` |
| **人評重點** | RQ1：`R1`；RQ2：情緒覺察／同理 |

### 3.3 I — Interpretive 體會

| | 內容 |
|--|------|
| **檢查** | 是否寫出想法、體會或學到的事；是否能連結自己的生活經驗；是否理解角色／故事意義／人際關係 |
| **引導** | 用故事事件支持道理；問「和你自己什麼經驗有關」 |
| **系統對照** | `I1`；輔助 SEL：`SEL_SOA`、`SEL_RS`；**生活連結**併入本段／反思深度（**不**新增 SEL ID） |
| **人評重點** | RQ1：`I1`＋生活連結；RQ2：同理／關係理解 |

### 3.4 D — Decisional 行動

| | 內容 |
|--|------|
| **檢查** | 是否提出未來行動；行動是否具體、可實行（情境／對象／做法） |
| **引導** | 「以後如果遇到類似情況，何時、對誰、怎麼做」 |
| **系統對照** | `D1`；輔助 SEL：`SEL_RD`（負責任行動）、`SEL_RS`、`SEL_SM` |
| **人評重點** | RQ1：行動具體性；RQ2：負責任行動 |

### 3.5 奇數週 SEL 融入方式（引導）

- SEL 以**輔助提問／層級估計**進入 GenAI feedback（現行注入 `sel_rubric`）。  
- **禁止**讓 SEL 成為「再想一想」的唯一主題而蓋過該段 ORID 主任務（與現行 RASF／敘事政策一致）。  
- 映射（研究用語 → 系統 ID）見 [`research_design_context.md`](research_design_context.md) 第五節。

## 四、偶數週整合寫作 AI feedback rubric

適用：第 2、4、6 週；`source=synthesis_feedback`；`stage=ALL`。

任務本質：把上一週 O/R/I/D **整理成一篇**完整反思短文，不是重寫四格。

### 4.1 五個檢查面向（研究目標）

| # | 面向 | 檢查什麼 | 引導什麼 |
|---|------|----------|----------|
| 1 | **完整性** | 是否含故事事件、感受、體會、行動 | 缺哪一塊就先補哪一塊 |
| 2 | **連貫性** | 四部分是否自然接起，而非硬貼 | 指出「哪兩段之間」可加銜接 |
| 3 | **反思深度** | 是否說明感受原因、故事體會、**生活連結** | 問原因／自己經驗／故事支持 |
| 4 | **SEL 表現** | 是否展現情緒覺察、同理、關係理解或負責任行動等 | 用**一個**短問句補強最弱的 SEL 面向；不一次打全部 |
| 5 | **行動具體性** | 最後是否寫出具體可做到的行動 | 補情境／對象／第一步 |

### 4.2 建議優先順序（有缺口時）

1. 完整性 → 2. 連貫性 → 3. 反思深度（含生活連結）→ 4. SEL 表現（輔助）→ 5. 行動具體性  

特殊規則（與現行啟發式對齊）：若偵測草稿**大量逐字貼上**上週 O/R/I/D（完整性通常已足），本輪**優先只談連貫性**。

### 4.3 開場應提醒的寫作順序（學生語）

1. 先說故事中讓你印象深刻的事件  
2. 再說你看到這件事時的感受（與原因）  
3. 接著說你從故事想到什麼或學到什麼  
4. 最後說以後遇到類似情況你會怎麼做  

### 4.4 現況 vs 目標（實作對照）

| 項目 | 現況（程式／playbook） | 本文件目標 |
|------|------------------------|------------|
| 完整／連貫／深度／行動 | 已在 synthesis coach playbook | 維持 |
| SEL 表現（具名面向） | **尚未**在整合 playbook 具名 | Phase 3 再改 prompt；本文件先定規準 |
| 正式自動計分 | 偶數週**不做** ORID/SEL 正式系統分 | **維持**：正式分用人評；不急著自動計分 |
| 貼上→連貫優先 | 已有 `looks_like_pasted_stage_paragraphs` | 維持 |

工程可選階段（A–D）與另一套「證據／扣題／結構／語言」描述見 `fastapi_backend/docs/SYNTHESIS_INTEGRATED_WRITING_SPEC.md`；**研究用人評／AI 引導五面向以本節為準**。

## 五、SEL 面向如何融入 feedback（總表）

| 研究用語 | 系統 ID | 主要掛鉤 |
|----------|---------|----------|
| 情緒覺察 | `SEL_SA` | 奇數 R；整合文感受段 |
| 同理理解 | `SEL_SOA` | 奇數 R／I；整合文體會／角色 |
| 關係理解 | `SEL_RS` | 奇數 I／D；整合文人際／分享 |
| 負責任行動 | `SEL_RD` | 奇數 D；整合文行動段 |
| 生活連結 | — | **I／反思深度**（不新增 criterion） |
| 自我管理（系統既有） | `SEL_SM` | 系統仍可估計；人評表可選評 |

原則：每次回饋仍以該週**任務主缺口**為主；SEL 最多帶**一個**短引導，服務 RQ2 但不稀釋 RQ1。

## 六、三段式格式（輸出契約）

實驗組學生可見回饋建議依序三小段，段首標題固定：

```text
你已經做到：
……

再想一想：
……

可以這樣修改：
……
```

- 每段 1～3 句短句即可。  
- 未達標：禁止「本階段完成／下一步進入 X」等完成語氣。  
- 已達標（奇數週 `ok=true`）：可用完成卡／鼓勵進入下一段（依現行 UI），勿再無限加要求。

---

## 七、不直接代寫答案的規則

1. 不提供可直接交卷的完整段落。  
2. 不重寫學生整篇整合稿。  
3. 示例最多到「句首／連接詞／半句方向」。  
4. 書中事實可提醒「回去對哪一幕」，但不要替學生填滿整個 O 段。  
5. 安全／注入／不當內容依系統安全檢查處理，不進入正常寫作引導。

## 八、控制組固定提示 vs 實驗組 AI feedback

| | 實驗組 | 控制組 |
|--|--------|--------|
| 內容 | 依學生**當下文句**個人化 | **固定**句型與文本提問，不依句動態改寫 |
| 介面 | AI 教練／「取得回饋」「取得整合回饋」 | `WritingPromptHelper` 翻頁提示 |
| 系統分 | 可有（探索用） | **不**產個人化 AI 系統分 |
| 正式比較 | 人評同一套 rubric | 人評同一套 rubric |
| 構念對齊 | ORID + SEL | 固定提示應**對應同一構念**（句型／提問），但非個人化 |

控制組素材：`nextjs-frontend/lib/orid/control-guide-pages.ts`（奇數 `getControlGuidePages`、偶數 `getSynthesisGuidePages`）。

## 九、之後 AI prompt 應如何依條件設計（給 Phase 2–4）

> 以下為**設計規範**；Phase 1 **不修改** prompt 程式。

| 輸入 | 應有行為 |
|------|----------|
| `condition=control` | 不呼叫個人化 LLM 寫作批改；僅固定提示（及既有非個人化規則路徑若保留） |
| `experimental` + 奇數 + `feedback_button` | ORID 主向度 + SEL 輔助 → JSON／層級 → 未過則三段敘事 |
| `experimental` + 偶數 + `synthesis_feedback` | 五面向目標版（含 SEL 引導）+ 單點缺口 + 貼上啟發式 |
| `stage` | 選對 O/R/I/D 規則與 SEL by_stage |
| `week` / 書包 | 注入對應書本脈絡（三書齊後） |
| `task_type` | `orid_stage` vs `synthesis` 使用不同 builder／playbook |

建議改動檔（**尚未改**）：

- 奇數週：`prompts/templates/writing_feedback.py`、`prompts/builders/writing_feedback.py`、`prompts/orid_playbook.py`、`prompts/builders/coach_chat.py`（narration）、`prompts/versions.py`
- 偶數週：`format_synthesis_coach_playbook`、`build_synthesis_coach_system_prompt`、`versions.py`（`synthesis_coach`）
- 測試：`tests/prompts/test_prompt_builders.py` 等

版本號：行為變更時遞增 `PROMPT_VERSIONS` 對應鍵，便於實驗記錄。

## 十、人評建議（與 AI 規準對齊，供正式分析）

### 10.1 奇數週作品

- ORID：`O1`／`R1`／`I1`／`D1` 各 1–4 級（可沿用系統等級描述，經教師檢核後定稿）。  
- SEL：至少評情緒覺察、同理、關係、負責任行動；生活連結併 I。  
- 兩組用**同一張**人評表。

### 10.2 偶數週整合短文

- 五面向各 1–4 級：完整性、連貫性、反思深度（含生活連結）、SEL 表現、行動具體性。  
- 建議雙評＋一致度（κ／ICC）。

系統自動分**不**取代上述人評。
